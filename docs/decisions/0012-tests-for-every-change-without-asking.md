# 0012: 規模に関わらずテストを書かせ、空の `check` には NOTE を出す

- 日付: 2026-10-07
- 状態: 採用

## 背景

小さいタスクでは `task-orchestrate` を使わない。そのとき効いている仕組みは次の 2 つだけだった。

- `AGENTS.md` の「実装後は `harness check` を回す。これが完了の客観条件」（常に読み込まれる）
- pre-commit の `check --fast`（init が `core.hooksPath` を設定する）

穴は 2 つあった。

1. **seed の `checks.sh` にはプロダクトの検査が無い**（`docs index exists` と `doctor: FAIL 0` だけ）。登録しないかぎり `harness check` は常に pass し、何も保証しない。init の最後の案内（「`checks.sh` に検査を登録する」）は導入直後に 1 回出るだけ。
2. **テストを書けという要求が実装役（`docs/roles/implementer.md` の TDD）にしか無い。** `task-orchestrate` を通らない作業にはテストの義務が無かった。

## 採用案

1. **`harness check` の最後に NOTE を出す。** 実行した検査のうち seed の検査名以外が 0 件なら「プロダクトの検査が 0 件。この pass は何も保証しない」と登録方法を出す。FAIL にはしない（init 直後に `check` が通ることは決定 0005 で守っている）。`--fast`（pre-commit）では出さない。seed の検査名がずれたら NOTE が出なくなるので、`tests/seed.sh` で init 直後に NOTE が出ることを検査する。
2. **共通ルール（`AGENTS.core.md`）に 1 行足す**: 「振る舞いを変えたらテストを足す（バグ修正は再現テストから）。テスト基盤が無い・書けないときは足さずに完了報告へ理由を 1 行書く。確認は求めない。」
   - ユーザーに毎回聞く形にしない。既定の動きとして書き、例外のときだけ報告に 1 行残す。docs・設定・文言の変更では何も言わない。
   - テスト基盤が無いプロジェクトで、エージェントがテストフレームワークや依存を勝手に入れないよう「足さずに理由を書く」を明記した。

1 と 2 は一組。1 だけだと新しいテストが書かれず、2 だけだと書いたテストが `check` で回らず自己申告に戻る。

## 落選案と落選理由

- **ハーネスがテストそのものを生成する**: 言語・フレームワークの知識がペイロードに入り、「依存は git と bash だけ」「プロジェクトのビルド／テスト基盤は呼ぶだけ」（`DESIGN.md` §12）が崩れる。テストを書くのはどのみちエージェントで、ハーネスの役目は要求と検証。
- **一律に「テストを必ず足す」**: docs・設定・見た目など意味のあるテストが書けない変更で、`assert true` やモックをなぞるだけのテストが量産される。検査の抜け道を自分で作ることになる（`DESIGN.md` 原則 4）。
- **「書くか、書かない理由を述べるか」をユーザーに確認する**: 小さいタスクのたびに確認が挟まり、使われなくなる。
- **ハーネスが「変更ごとにテストが増えたか」を機械で強制する**: 上と同じく抜け道を量産する。なお、プロジェクトが自分で `checks.sh` に登録する「テスト 0 件で green は不合格」（`checks.seed.sh` の例）は否定しない。
- **Claude Code の Stop フックで毎ターン `check` を回す**: 質問に答えるだけのターンでも走って遅く、失敗時にループし得る。Claude 固有なので Codex 側にも同等物が要る。コミット時点は pre-commit が既に見ている。
- **NOTE の判定に「`checks.sh` が雛形のままか」を使う**: seed は manifest にハッシュを持たない（`sha256: "-"`）。持っていても、無関係な検査を 1 件足しただけで警告が消える。

## 影響・やり直す条件

- seed の検査名を `check.sh` の `case` に直書きしている。配布先からはペイロードの `checks.seed.sh` を読めず（source が URL のこともある）、seed の検査に印を付ける方式は古い配布先の `checks.sh` に印が無いので使えない。seed の検査を足す・改名するときは `check.sh` も揃える。揃え忘れは `tests/seed.sh` が落ちて気づく。
- `AGENTS.core.md` は 60 行（検査の上限ちょうど）。次にルールを足すときは既存の行を削る。
- docs だけのリポジトリなど、テストを書きようが無いプロジェクトでは NOTE が出続ける。止める手段は実害が出てから足す（決定 0010 の流儀）。
- 2 の効果（エージェントが確認なしにテストを書くか）は実プロジェクトでの配布後に確かめる。書かない・過剰に書く等が観測されたら文言を見直す。
