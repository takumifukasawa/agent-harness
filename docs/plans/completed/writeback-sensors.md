## 目的（何ができれば完了か）

統括を縛るものが `task-orchestrate` スキルの**文章（guide）しかない**状態を解消し、**設計が言う「検査 > スキル > 文章」の順序どおりに sensor へ落とす**。2026-09-21〜22 の 2 題材で実際に漏れた 4 件のうち、まだ検査で捕まえられない半分が対象。

## 受け入れ条件（検査で確認できる形に）

[spec](../../spec/writeback-sensors.md) の A / B / C。**A と C は回帰シナリオを条件に含める**（この題材の性質上、検査が無ければ同じことが再発する）。B は「そもそも書かせない」なので機械での強制はしない。

## 決定ログ（日付・決めたこと・理由・落選案）

- **2026-09-22 / A はコミット数で見る。** 日付では同じ日の 10 コミットを捕まえられない（実際に取り逃した）。落選: 差分の行数・ファイル数（閾値の感覚がつかみにくい）、sensor にせず guide のまま（今日それで漏れた）
- **2026-09-22 / B は「そもそも書かせない」。** 腐る数値を雛形から外し、叩き方を書く。落選: `gc` が実測と突合（`gc` が 90 秒かかるようになり、今の 1 秒だから毎回回せるという利点を失う）、今回は触らない（handoff は `session-catchup` の入口なので古い数値の害が大きい）
- **2026-09-22 / C は plan と同じパターンで見る。** T04 の「装飾と括弧を落とした中核語の前方一致」で表記揺れの誤検知は解消済みなので、前回（onboarding-polish）の落選理由が消えた
- **2026-09-22 / 3 タスクすべて逐次にする。** T01 と T03 は `gc.sh` と `tests/gc.sh`、T02 は CHANGELOG と導入コピーで競合する。**並列可否は「触るファイルが重なるか」ではなく「`update` のような全体同期コマンドを含むか」で見る**（`docs/learnings.md` 2026-09-21）

- **2026-09-22 / `--commits` の既定値は 10。** このリポジトリの `docs/handoff.md` 更新間隔ごとの「非 docs コミット数」を実測して決めた（**中央値 2、5 件以下が 30 区間中 26、外れ値 7 / 9 / 12 / 14**）。実際に見逃した「10 コミット」の実例に一致させてある。落選: 5（通常のセッションで警告が出すぎる）、20（今回の見逃しを拾えない）

- **2026-09-22 / 雛形には注記だけを書き、数値の Before/After の実例は書かない。** 雛形に数値の実例を書くと、それ自体が腐る見本になる

## 最終レビュー（2026-09-22、1 回）

観点 4 つを下位モデルで並列に。前の題材と同じく既定の「並行性 / 認可」は外し、**検査の実効性 / クロス環境と性能 / 仕様突合と完結性 / ドキュメントと書き戻し**に差し替えた（この題材は検査が空洞なら成果がゼロで、成果物が bash と文章のため）。**指摘 8 件 → 重複排除して 7 件。**

| 観点 | 件数 | 主なもの |
|---|---|---|
| 検査の実効性 | 1（中） | **G22 が C3 のガードを守れていない**（ガード行を消しても 24/24 PASS）。A・C の他のロジックは 6 パターン壊して該当シナリオが赤くなることを実測 |
| クロス環境と性能 | 2（中） | **`spec_plan_file()` の二乗化**（spec300/plan1500 で 50s）/ **`core.quotePath` で非 ASCII パスが A3 判定から漏れる** |
| 仕様突合と完結性 | 5（高 1・低 4） | handoff 未更新 / NEXT 番号の重複 / A3 混在コミットの回帰なし / spec 索引漏れ / G24 の単発 FAIL |
| ドキュメントと書き戻し | 1（高） | handoff 未更新（仕様突合と同じ指摘） |

**反証は回していない**（条件は「単独報告」かつ「修正コスト高」の両方。全件が修正コスト低、または確度不明で 1 件も該当せず）。

**いちばん重い指摘は 2 体が独立に報告した**: **この題材が防ごうとしている「統括の書き戻し漏れ」を、この題材の実装セッション自身が再現していた**（`docs/handoff.md` が T02 完了時点で停止）。しかも**今回新設した sensor のどちらにも引っかからない**ことが実測で確認された（A は handoff 以降の非 docs コミットが 1 件で閾値 10 に届かない。C は handoff を対象にしていない）。**A の sensor が効くのは「セッションを跨ぐ放置」であって、「同一セッション内で統括が書き戻しそびれる」ケースは素通りする**というのが、この題材で分かった限界。

**処理**: T04 で 2 件（gc.sh の実害）、T05 で 2 件（検査の穴）、統括が直接 3 件（handoff の書き戻しと NEXT 番号、spec 索引）。**未解決 1 件**: G24 がフルスイート初回実行で単発 FAIL したという報告（18 回連続では再現せず、原因未特定）。重大度を下げて `progress.json` の `final_review.unresolved_findings` に残した。
