## 最終レビュー（2026-09-21〜22、1 回）

観点 4 つを下位モデルで並列に。前の題材の「機能の完結性」を **「検査の実効性」に独立**させた（この題材は検査が空洞なら成果がゼロのため）。**指摘 10 件 + 統括の発見 1 件。**

| 観点 | 件数 | 主なもの |
|---|---|---|
| **検査の実効性** | **0** | 4 検査すべて実装を壊して fail することを確認。`gc` は見逃し／過剰検出の両方向で落ちる相補的な作り |
| **クロス環境** | **0** | bash 3.2 の最小再現、`mkfifo` 失敗時のフォールバック、CRLF の計画ファイル、source ガード 3 系統まで実走 |

| ドキュメント | 5（高 2） | plan と handoff（統括の漏れ）/ 案内文の取り残し / 限定の未記載 / README |
| 統括の発見 | 1（中） | `gc` の判定がレビュー中という正常な途中状態を考慮していない |

**反証（単独報告かつコスト高の 2 件に 1 体）**:
