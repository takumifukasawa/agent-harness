# no-silent-failures — 黙って通るものを機械で止める

状態: **反復フェーズ**。2026-09-21 起票、同日に未確定 2 件を合意して分解した。

## 目的

2026-09-21 の作業で、**「失敗しているのに誰も気づけない」形の不具合が 3 つ**出た。根はどれも同じで、**黙って通るから気づけない**。個別に直すのではなく、この 1 題材でまとめて塞ぐ。

| # | 黙って通るもの | どう気づけないか |
|---|---|---|
| **#15** | `hash_server_start` が `exec 3<>... 2>/dev/null`（**コマンドを伴わない `exec`**）で**シェル全体の stderr を恒久的に `/dev/null` へ**流す | 以後どんなエラーも出ない。`mkdir -p` の失敗で `init` が**無言終了**し、`manifest.json` が無いので `status` / `doctor` は「未導入」としか言わない。中途半端に配られた約 28 ファイルの残骸が残る |
| **#14** | case 衝突の検出が `ownership=seed` のみ。`managed`（`.githooks/pre-commit` 等）は対象外 | `.githooks/Pre-commit`（case 違い）があると `doctor` は「OK git hooks（... 実行可能）」と**恒久的に緑**を返す。実際に効いているフックは無関係な内容のまま |
| **（新規）** | **統括自身の書き戻し漏れを機械で見ていない** | 実装役は `files_scope` と検査で縛れるが、統括が `plan` / `spec` の状態欄を実態と合わせ忘れても誰も止めない。2026-09-21 の最終レビューで実際に 2 件拾われた（人間のレビューが無ければ残っていた） |

**共通する失敗の形**: 「壊れている」と「正常」が**出力から区別できない**。ハーネスは「`check` が通ることが完了の客観条件」（`AGENTS.md`）を土台にしているので、**気づけない緑はこの土台を崩す**。決定 0007（フックが実行不可なら FAIL）と同じ論理をここにも通す。

## 受け入れ条件

### A. エラーが見える（#15）

- A1. `hash_server_start` が失敗しても、**それ以降の stderr が消えない**（`exec` のリダイレクトをシェル全体に永続適用しない）
- A2. `init` / `update` が途中で失敗したとき、**何が失敗したかが stderr に出る**（無言終了しない）
- A3. **`manifest.json` を書く前に失敗した場合、中途半端に配られたファイルがあることが分かる**（残骸に気づける。消すかどうかは別問題）
- A4. 回帰を止める検査がある。**「stderr が生きているか」を機械で確かめる**（例: 常駐サーバを起動した後にわざとエラーを起こし、出力を捕まえる）
- A5. ハッシュ常駐サーバの高速化（版 0.6.0 / CS-B1）を壊さない。`init` / `update` の所要が目に見えて悪化しない

### B. 偽の緑を出さない（#14）

- B1. `managed` ファイルが case 違いの既存ファイルと衝突している状態を **`doctor` が検出する**（`.githooks/pre-commit` を含む）
- B2. その状態で `doctor` が「OK」を返さない
- B3. 回帰を止める検査がある
- B4. `seed` 側の既存の検出（#13 の `CASE-CONFLICT`）と**同じ語彙・同じ直し方**で案内する（利用者から見て 2 つの別物にしない）

### C. 統括の書き戻し漏れを機械で見る（新規）

- C1. **`docs/plans/active/` の計画で、タスク表と状態欄が矛盾している状態を検出する**（2026-09-21 合意）。具体的には次の 2 つ:
  - タスク表の行がすべて `done` なのに、状態欄が「完了」になっていない（＝終わったのに書き戻していない）
  - 状態欄が「完了」なのに `active/` に置かれたまま（＝畳み忘れ）
- C2. 検出は **`harness gc`** の一部として出す（docs の腐敗検知はすでに gc の担当）
- C3. 誤検知で埋もれさせない。**「書き方が少し違う」程度で警告しない**（gc の既存項目と同じ水準）
- C4. 回帰を止める検査がある（`tests/gc.sh` に足す）

## 範囲外（やらないこと）

- **中途半端に配られたファイルの自動ロールバック**（A3 は「気づける」までが範囲。消すのは別の設計判断で、失敗の種類によっては消してはいけない）
- `case` 衝突の自動修復（決定済み: 検出と案内だけ）
- 統括の**作業そのもの**を機械化すること（書き戻しは人／統括の仕事。検査は「漏れを教える」までが範囲）

## 合意済みの決定（2026-09-21）

- **C が見るのは「タスク表と状態欄の矛盾」だけ。** 2026-09-21 の最終レビューで拾われた 2 件はこれで止まる。判定が機械的で誤検知が少ないのが理由。落選: spec との食い違いや参照切れも見る（拾える範囲は広いが、表記揺れでの誤検知が増え、gc の既存項目を埋もれさせる。C3 に反する）、人間向けチェックリストだけ（今回もスキルに書いてあって漏れた。文章では止まらない）
- **A3 は「気づけるだけ」。** 失敗時に「どこまで配ったか」「manifest は書いていない」を出し、`doctor` も残骸を指摘する。**自動ロールバックはしない**（失敗の種類によっては消してはいけないし、既存ファイルを誤って消すリスクを背負う）
