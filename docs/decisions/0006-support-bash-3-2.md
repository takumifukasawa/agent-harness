# 0006: bash 3.2 を切らない（macOS 既定の bash で動く形に落とす）

- 日付: 2026-09-20
- 状態: 採用

## 背景

ハーネスの前提は「エージェントと OS を問わず同じ役割を果たす」（`docs/spec/cross-env-support.md`）。しかし実機で確かめたのは Windows × Claude の 1 象限だけだった。2026-09-20、作業機を macOS（Darwin 24.6 / arm64 / ja_JP.UTF-8）に移して初めて実機で回した。

macOS の既定 bash は **3.2.57**（Apple が GPLv3 を避けて 2007 年版から更新していない。今後も変わらない見込み）。この前提で `harness check` を回した結果:

```
harness check: pass=9 fail=4
  failed: seed checks are green
  failed: doctor scenarios      （tests/doctor.sh: pass=2 fail=36）
  failed: update scenarios
  failed: doctor: FAIL 0
```

**4 件のうち 3 件は根本原因が 1 つ**だった。`harness init` が即死するのでテストの setup が全滅していた:

```
bin/harness: line 355: declare: -A: invalid option
```

さらに、静的走査（`docs/tech-debt.md` #3）では挙がっていなかったブロッカーを 1 件見つけた。**bash 3.2 + UTF-8 ロケールでは `"$var日本語"` が壊れる**:

```bash
$ /bin/bash -c 'set -u; v=x; echo "[$v。]"'
/bin/bash: v?: unbound variable      # 「。」の先頭バイトを変数名に食い込ませる
$ /bin/bash -c 'set -u; v=x; echo "[${v}。]"'
[x。]                                 # 波括弧で括れば通る
```

ハーネスのメッセージはすべて日本語なので、これは広く効く。実際 `harness doctor` は B10（`doctor.sh:421`）でこの形に当たって異常終了し、**FAIL 行は出るのに総括行まで届かない**状態だった。

一方、実測で分かった良い知らせもある。bash 4+ 依存は**全部で 3 箇所しかない**（`declare -A` 1 / `mapfile` 2）。`"$var日本語"` は 24 行。合わせて 27 箇所で、すべて機械的な置換で済む。

また `docs/tech-debt.md` #3 の前提のうち 1 件は**この機では当たらなかった**: `sha256sum` は `/sbin/sha256sum` に、`jq` は `/usr/bin/jq` に Apple 提供のものが入っていた（macOS 15 以降）。古い macOS には無いので、リスクとしては残る。

## 採用案

**bash 3.2 を切らない。macOS 既定の bash でそのまま動く形に落とし、再発は検査で止める。**

直す対象（実測 27 箇所）:

| 対象 | 箇所 | 直し方 |
|---|---|---|
| `declare -A OLD_HASH OLD_SRC_HASH` | `bin/harness:355`（1） | 連想配列を使わない形に置換する |
| `"$var日本語"` | 24 行（`bin/harness` 6 / `doctor.sh` 7 / `gc.sh` 3 / `tests/doctor.sh` 5 / `tests/seed.sh` 2 / `tests/update.sh` 1） | `${var}` に括る |
| `mapfile` | `doctor.sh:76-77`（2） | `while read` に置換する。外部コマンドが全滅した時のフォールバック経路なので実害は出ていなかったが、3.2 で動く前提を崩さない |

未到達のブロッカー（`date -d` / `sed -i` の引数）は、`init` が通るようになって実際に踏んだ時点で直す。**先回りで直さない**（踏んでいない = その経路が macOS で使われていない可能性があり、直しても検証できない）。

理由:

- **目的に直結する。** spec の目的は「PC を問わず同じに動く」。macOS 既定が 3.2 のまま変わらない以上、「4+ 必須」は永久に `brew install bash` を新規ユーザーに強いる。clone して即動くことの価値が、失うものより大きい。
- **実測コストが小さい。** 27 箇所、すべて機械的。事前の見積もり（「影響範囲と手間が大きく違う」）より遥かに軽かった。**実機で回さなければこの数字は出なかった。**
- **再発を機械で止められる。** `$` の直後が識別子で、その次が非 ASCII の箇所を走査する検査を足せる。`declare -A` / `mapfile` / `readarray` の禁止も同じ形で書ける。「直した」で終わらせない（受け入れ条件 C1）。

## 落選案と落選理由

- **bash 4+ 必須と割り切り、doctor の入口だけ 3.2 対応する**（24 行の `${var}` 化だけ行い、`declare -A` と `mapfile` は温存）。案内は確実に届くようになるが、**新規ユーザーは結局 `brew install bash` をしないと何も始められない**。27 箇所のうち 24 箇所を直すので、コスト差はわずか 3 箇所しかない。差が小さいのに得るものが大きく違うので落選。
- **bash 4+ 必須で現状維持**（修正 0 箇所）。`doctor` の B1 が FAIL を出すので「黙って壊れる」ことはない、という建て付け。落選理由は 2 つ。(1) 実測では doctor 自身が B10 で異常終了し、**総括行まで届かない**ので「止まるから安全」が成り立っていない。(2) 受け入れ条件 A2（`harness check` 全件 pass）が「bash 4+ で回した場合」という但し書き付きになり、A1〜A5 が検証する対象が曖昧になる。
- **環境差を吸収する互換レイヤを自作する**（連想配列のエミュレーション層など）。spec の範囲外に明記済み（「大掛かりな抽象化はしない。個別に直す」）。27 箇所の個別修正のほうが軽い。

## 影響・やり直す条件

- **今後 `declare -A` / `mapfile` / `readarray` は使えない。** 連想配列が欲しくなったら、区切り文字つきの単一変数か一時ファイルで代用する。この制約は検査で機械的に強制するので、忘れても止まる。
- **`"$var日本語"` は書けない。** 変数展開の直後に非 ASCII が来る場合は `${var}` に括る。これも検査で止める。日本語メッセージを書くこのリポジトリでは踏み続ける罠なので、`docs/learnings.md` にも「再発したらまず何を見るか」の形で残す。
- **`tests/` に OS 分岐を持ち込まない**（受け入れ条件 A5 の既定）。両方で通る書き方に直す。
- **やり直す条件**: bash 3.2 で書けないことが本質的に必要になったら（例: 連想配列なしでは成立しない機能を入れる）、この決定を覆して 4+ 必須に切り替える。そのときは `doctor` の B1 を「FAIL + 導入手順」として正式な仕様に格上げし、B10 より前に置いて**確実に総括まで出す**（今回の失敗の再発防止）。
- **古い macOS（15 未満）は未検証のまま。** `sha256sum` / `jq` が無い前提の経路は、この機では確かめられなかった。`docs/tech-debt.md` #3 を更新する。
